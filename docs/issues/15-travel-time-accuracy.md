# #15 이동시간 정확도 원인 조사와 보정 전략 선택

## 결론

- 현재 값은 실제 여정시간이 아니라 **인접역 운행시간 합 + 환승당 고정 3분**이다.
- 2026-08-31 09:00 KST 시간표 기준 `신대방삼거리 → 당산`은 정적 13분,
  서울교통공사 기준 22분 10초이며 분 단위 올림 시 23분이다.
- 12개 경로 모두 정적값이 작았다. 전체 MAE는 8.5분, MAPE는 28.7%다.
- 오차는 전역 상수로 설명되지 않는다. 직접 경로 MAE는 3분, 1회 환승은 9분,
  다회 환승은 15분으로 환승 횟수에 따라 커진다.
- **정적 보정**을 선택한다. 운행 구간과 환승을 별도 보정하고 외부 API는 런타임에
  호출하지 않는다. 첫 열차 대기와 역 출입을 제외한다는 라벨을 함께 적용한다.

이 문서는 조사와 전략 선택만 기록한다. 운영 계산과 문구는 변경하지 않았다.

## 측정 방법

### 정적값

기준 커밋은 `8e01a21`이다. `STATIC_NETWORK`에서 출발역의 모든 노선 노드를 0으로
시작하는 현재 Dijkstra와 동일한 조건으로 predecessor를 기록해 경로를 역추적했다.

- 선로 간선: 국가철도공단 운행정보의 일반열차 인접역 출발→도착 중앙값을 분 단위로
  반올림한 값
- 환승 간선: 같은 물리역의 노선 노드 사이 고정 3분
- 포함하지 않는 값: 중간역 정차시간, 첫 열차 대기, 시간대별 배차, 역 출입 보행

원본과 생성 규칙은 [STATIC-NETWORK.md](../loop/STATIC-NETWORK.md)에 고정되어 있다.

### 기준값

[서울교통공사 지하철역 최단경로이동정보](https://data.seoul.go.kr/dataList/OA-22724/A/1/datasetView.do)의
`getShtrmPath` 최소시간 경로를 사용했다.

- 검색시각: `2026-08-31 09:00:00` KST, 평일
- 요청: `schInclYn=Y`, 기본 `searchType=duration`
- 표시값: `totalReqHr / 60`을 올림한 정수 분
- 경로와 환승: 응답의 `paths`, `trsitNmtm`, `trfstnNms`
- 성격: 첫 열차 출발부터 최종역 도착까지의 역-대-역 시간표 경로다. 검색시각부터
  첫 열차 출발까지와 역 출입 보행은 포함하지 않는다.

샘플 키는 조사 호출에만 사용했다. 서울 열린데이터광장은 정식 서비스에
[인증키가 필요하고 샘플 키는 제한된다고 명시](https://data.seoul.go.kr/together/guide/useGuide.do)한다.
따라서 이 조사 호출을 운영 의존성으로 만들지 않는다.

## 원인 순위

1. **환승 비용 과소모델링** — 알려진 사례에서 4분 30초, 전체 표에서는 환승
   단계가 늘 때마다 범주 MAE가 약 6분씩 증가했다. 고정 3분은 보행과 다음 열차
   대기를 동시에 대표하지 못한다.
2. **중간역 정차와 간선 집계** — 환승이 없는 경로도 MAE 3분이다. 알려진 사례의
   동일 노선 구간에서 정차 3분 10초와 주행 간선 차이 1분 30초가 측정됐다.
3. **잘못된 최단경로 선택 가능성** — 12개 중 2개에서 노선/환승역이 달랐다.
   `북한산우이 → 신대방삼거리`는 정적 경로가 기준보다 환승을 한 번 더 선택했고
   오차도 최대 21분이었다.
4. **첫 열차 대기** — 이번 기준 API의 `totalReqHr`에도 포함되지 않아 13 대 23의
   측정 오차에는 0분이다. 다만 사용자가 문구를 실제 출발부터의 여정시간으로 읽으면
   여전히 빠진 값이므로 라벨로 경계를 밝혀야 한다.
5. **역 출입 보행** — 양쪽 모두 역-대-역 측정이라 이번 오차에는 포함하지 않았다.
   문전 이동시간으로 확장하지 않는 한 계산에 섞지 않는다.

## 권장 전략과 허용오차

### 선택: 선로/환승 분리 정적 보정

현행 `3분 × 환승 + 나머지 선로시간`을 각각 별도 특성으로 보정한다. 12개 값에 절편
없이 적합한 탐색식은 다음과 같다.

```text
보정 후보 = 1.278 × (현행 정적값 - 3 × 정적 환승수) + 6.561 × 정적 환승수
```

이는 전역 `+10`이 아니다. 같은 표에 재적합한 결과이므로 생산 계수가 아니라 후속
검증의 가장 작은 가설이다. 정수 반올림 시 표본 MAE 1.9분, MAPE 9.0%, 최대오차
4분이었다. 30개 분리 표본의 홀드아웃 기준을 통과할 때만 채택한다.

### 허용오차와 회귀 기준

후속 구현은 고정된 30개 경로(직통 10, 1회 10, 다회 10)를 훈련/홀드아웃으로
분리하고 다음을 모두 만족해야 한다.

- 홀드아웃 MAE ≤ 5분
- 홀드아웃 MAPE ≤ 20%
- 홀드아웃 p95 절대오차 ≤ 10분
- 각 환승 범주의 MAE ≤ 6분
- 평균 부호오차(보정값 - 기준값) -2분 이상 +2분 이하
- `신대방삼거리 → 당산` 절대오차 ≤ 5분
- 기준보다 환승을 두 번 이상 더 쓰는 경로 0개
- 외부 런타임 요청과 새 자격증명 0개

하나라도 실패하면 계수를 임의 조정해 배포하지 않고 정적 보정 전략을 다시 검토한다.

### 사용자에게 보여줄 의미

- 라벨: `정적 이동시간 추정`
- 보조문구: `열차 탑승·환승 기준 · 첫 열차 대기 및 역 출입 제외`

첫 열차 대기와 출입 보행을 계산하지 않으므로 `실제 소요시간` 또는 단정적인
`예상시간`으로 표시하지 않는다. 이 이슈에서는 문구를 변경하지 않는다.

## 후속 보정 이슈 #16

승인된 후속 구현은 GitHub
[#16](https://github.com/borobong2/gatigo-web/issues/16)으로 생성했다.

### 제목

`[Loop 0] Calibrate static travel time by track and transfer costs`

### 결과

런타임 외부 호출 없이 정적 이동시간을 선로와 환승 특성으로 보정하고, 표시 의미를
실제 계산 범위와 일치시킨다.

### 범위

- 현재 경로 추적에서 선로시간과 환승 수를 분리한다.
- 이 문서의 12개 경로에 18개 홀드아웃을 더해 직통/1회/다회 각 10개를 고정한다.
- 훈련 데이터로 단순 계수를 적합하고 홀드아웃에서 위 허용오차를 검증한다.
- 통과한 계수만 추천 계산에 적용하고 `정적 이동시간 추정` 라벨·보조문구를 적용한다.
- 알려진 사례, 경로 범주, 추천 정렬 결정성을 자동 회귀로 남긴다.

### 제외

- 외부 경로 API 런타임 호출, API 키, 유료 구독
- 시간대별/실시간 시간표, 첫 열차 대기, 역 출입, 버스
- 전역 `+10`, 방/공유/지도/맛집/모바일 변경

### 완료 조건

- 위 8개 회귀 기준이 모두 통과한다.
- `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm format:check`, `pnpm build`가 통과한다.
- 기준을 통과하지 못하면 계산·문구를 배포하지 않고 결과만 #15에 기록한다.

#16 구현이 끝날 때까지 Gate 0(#9)은 차단 상태로 유지한다.
